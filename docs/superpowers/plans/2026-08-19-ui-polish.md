# UI Polish (Theme-Driven Animation & Color) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the visual-polish gaps identified in `docs/roadmap-audit-2026-08-19.md` Track 5 — apply the existing `.gitlore-enter` entrance animation where it's currently missing, add a FLIP transition to Rebase Editor's drag-reorder, and give Launchpad's board columns a semantic accent color — all using GitLore's existing theme-driven infrastructure, no hardcoded hex, no custom fonts, no new dependency.

**Architecture:** Every change here reuses a mechanism that already exists elsewhere in the codebase (the `.gitlore-enter` keyframe in `media/shared.css`, VS Code's own `--vscode-charts-*` CSS custom properties, `vscode.setState()`/`getState()` for the webview's built-in state-persistence API). Two of the four tasks need a specific correctness fix beyond "just add the class": Commit Graph and Rebase Editor both fully replace `webview.html` on every re-render (Commit Graph on every "Load More"; Rebase Editor on every document edit, which includes every drag-drop reorder), so naively adding `.gitlore-enter` to their rows would replay the animation on *every* row on *every* re-render — a flicker regression, not polish, and in direct tension with CLAUDE.md §20's "no decoration animations/transitions — they flicker." Tasks 1 and 3 below specifically avoid that.

**Tech Stack:** TypeScript (strict), vanilla webview CSS/JS (no framework), `node:test` + `node:assert/strict` for render-output unit tests.

**Spec:** `docs/roadmap-audit-2026-08-19.md` (Track 5, and Top-5 item #5)

## Global Constraints

- No hardcoded hex colors — every color comes from a `--vscode-*` CSS custom property (CLAUDE.md §18).
- Every animation/transition respects `prefers-reduced-motion` — each `media/*.css` file already has a blanket `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { transition: none !important; animation: none !important; } }` rule; client-side JS-driven transforms (Task 3) must additionally check `matchMedia('(prefers-reduced-motion: reduce)').matches` before applying an animated transform, since that CSS rule alone can't cancel a JS-set inline `transform`/`transition` style.
- No decoration animations/transitions in the *editor* itself (CLAUDE.md §20) — none of this plan touches editor decorations; it's webview-only.
- Never rely on color alone to convey meaning (CLAUDE.md §18) — Task 4's column accent is supplementary to the existing text label (`BUCKET_LABELS[bucket]`), never a replacement for it.
- No new runtime dependency.

`RebaseEditorProvider.resolveCustomTextEditor`'s `render()` re-runs on every `onDidChangeTextDocument` event, which fires on every drag-drop reorder (the drop handler sends a `reorder` message that the extension applies as a document edit).
```javascript
row.addEventListener('drop', (e) => {
  e.preventDefault();
  const to = Number(row.dataset.index);
  if (draggedIndex !== null && draggedIndex !== to) {
    if (!window.matchMedia('(prefers-reduced-motion: reduce)').matches) {
      const positions = {};
      for (const r of rowsEl.querySelectorAll('.rb-row[data-sha]')) {
        positions[r.dataset.sha] = r.getBoundingClientRect().top;
      }
      vscode.setState({ flipPositions: positions });
    }
    reorder(draggedIndex, to);
  }
  draggedIndex = null;
});
```

Then, near the top of the script (right after `const rowsEl = document.getElementById('rows');`), read back the previous positions and apply the FLIP transform to whichever rows moved:

```javascript
const previousState = vscode.getState();
if (previousState?.flipPositions) {
  for (const row of rowsEl.querySelectorAll('.rb-row[data-sha]')) {
    const before = previousState.flipPositions[row.dataset.sha];
    if (before === undefined) {
      continue;
    }
    const after = row.getBoundingClientRect().top;
    const delta = before - after;
    if (delta === 0) {
      continue;
    }
    row.style.transition = 'none';
    row.style.transform = `translateY(${delta}px)`;
    // Force a layout flush so the browser registers the starting transform before the
    // transition below is applied — otherwise it would just jump straight to the end state.
    row.getBoundingClientRect();
    row.style.transition = 'transform var(--gitlore-motion)';
    row.style.transform = '';
  }
  vscode.setState({});
}
```
